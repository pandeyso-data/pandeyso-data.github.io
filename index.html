About

I work as a Senior Member Technical at Broadridge Financial Solutions, where I have spent around seven years on enterprise implementation and the data flows behind fintech operations. My work sits across configuration, scheduled batch execution, database processing, and validation — making sure that what a requirement asks for is what the system actually produces.

I think in pipelines. A change usually starts as a requirement, becomes YAML or configuration, runs through batch jobs and database processing, gets validated, and moves through Datamart and staging layers into downstream processing and reporting. I am most useful in the middle of that chain: setting things up correctly, checking the data at each handoff, and troubleshooting when a run does not match expectations.

Lately I have been building on that foundation on purpose — strengthening SQL and Python, learning data engineering concepts, ETL and pipeline design, and Apache Spark, and getting practical with modern AI tools. A lot of this is structured through the IISc Agentic AI program, where I am learning spec-driven development: writing a clear specification before writing code.

How the work flows

A plain-English view of the pipeline my work runs across.

  1. Requirement

    What the business needs, stated clearly.

  2. YAML / Configuration

    The requirement expressed as parameters the system reads.

  3. Batch Execution

    Scheduled jobs run the work at volume.

  4. Database Processing

    Data is transformed and stored through database logic.

  5. Validation

    Checks confirm the output is complete, consistent, and correct.

  6. Datamart / Staging

    Validated data lands in structured layers for wider use.

  7. Downstream Processing

    Other processes consume that data.

  8. Reporting

    Stakeholders see the results.

My contribution concentrates in configuration, execution, validation, and troubleshooting — the stages where correctness is won or lost.
